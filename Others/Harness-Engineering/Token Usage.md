
# /usage 
- Context Window - 한 요청에 같이 실리는 것 전부 => 지금까지 오간 대화 + 새로운 대화 

# /compact를 실행하면 지금까지의 대화 즉 context Window를 줄여준다. 
- 클로드가 자동으로 하는 경우도 있다
- 이또한 비용(토큰)이 든다
- 작업중에 messages가 유난히 커져있다면 이 명령어를 쓸 때다.

# /clear 를 사용해서 아예 대화를 지워버릴 수 도 있다.
- 아무것도 남아있지 않다
- 비용도 없다.


# /context 를 이용하면 context usage를 볼 수 있다.
- 파일을 전체를 읽고 뭔가를 하게된다면 이 사이즈가 커질수록 메세지의 토큰이 점점 커진다.
- 내가 만약 무슨 구조인지, 어디에 무엇이 있는지 안다면, 나는 내가 원하는 부분만 명시해서 요청해야 한다. 범위를 좁히지 않으면 읽어오는 내용도 다 message context에 쌓이기 때문이다!

# 더 나아가기

- 입력 값 가운데 매번 반복되는 앞 부분은 더 싼 값에 처리가 가능하다.
-> 토큰 최적화가 된다
-> 매 요청마다 앞 부분, 즉 지침 파일과 지금까지의 대화는 그대로 반복
-> 1. 처음 담아둔다 = 캐시쓰기
-> 2. 담아둔걸 꺼내서 쓴다 = 캐시 읽기

캐시가 깨진다
- 쓰고있는 모델을 바꾸는 경우
- 지침 파일을 고쳐서 다시 읽히는 경우
- 앞서 배운 /compact
- TTL 이 존재합니다 -> 시간이 지나면 사라짐
